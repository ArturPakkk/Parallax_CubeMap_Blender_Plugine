# Parallax_CubeMap 2.0.0: audit and behaviour

Audited input: PX_CubeMap_Windows_1.3.1.zip, SHA256
f6b4bc5374a9109a69223a687e611cde60a1ec7fab02a833d60a160d9d581e5f.
The archive contained Python, two EXRs, documentation and the GPL license.
Entry paths, types, expanded sizes and CRCs were checked before extraction.

## Reproduced and fixed

- After Debug > Restore > Assign, version 1.3.1 did assign a material in the tested
  scenes, but kept Debug enabled. Its Debug button was active even after the
  material slot was removed. A fresh assignment now starts with the room, and
  Debug is available only when the selected objects have the material.
- A shared material keeps its Debug mode while other windows still use it.
  Repeated assignment on an existing window also preserves the selected mode.
- Assigning the first slot on a partially selected empty mesh implicitly changed
  unselected faces. Missing slots used by untouched/hidden faces are now padded
  with empty bindings before assignment.
- An injected error during an Edit Mode assignment left a phantom Object slot.
  Rollback now clears that slot as well as restoring face indices and backups.
- The addon keeps real material references in the blend file, including original
  DATA/OBJECT bindings. Renamed original materials and removed original slots work.
  Restoring an older 1.3.1 backup was checked in a separate Blender process.
- The new addon rejects simultaneous registration with PX CubeMap Windows.
  It reuses compatible old Debug_Parallax materials after the old addon is disabled.

The exact failure in a user's unsupplied blend file cannot be established from
a screenshot. The tested state transitions and the additional failures above
are covered by regression tests.

## Security review

Runtime imports are limited to Blender and standard-library helpers.
No network, subprocess, shell, dynamic execution, telemetry, credential access,
preference writes, persistent timers, handlers or keymap changes are used.
The addon reads only its bundled EXRs; it does not save user blend files itself.
Changes are limited to material bindings, its own backup properties/face attribute,
and newly created material/image/node data. Existing foreign or rewired materials
are rejected instead of being overwritten.

The package uses an explicit file allowlist, fixed ZIP metadata and byte-for-byte
verification after packaging. Source-only files, profiles, caches and Git metadata
are excluded. The debug EXR retains its author-confirmed original bytes. The old room EXR of
unknown provenance was replaced with an original scene generated by tools/create_room.py.
This is a code and behaviour review, not a claim that Python extensions are sandboxed.

## Tested locally

Windows, Blender 4.5.15 LTS, factory scenes and isolated test profiles:
the original material/UV/render/conflict suites; new repeated Debug/Restore/Assign
tests; native UI Undo/Redo; English/Russian UI strings; real ZIP installation;
disable/enable; save/reopen; legacy backup migration; injected-error rollback.
Compact results and hashes are recorded in verification.json.

GitHub Actions additionally runs packaging checks and integration tests in the
official native Blender 4.5.15 and 5.0.1 builds, verified against pinned SHA256 values. Its actual run status is recorded by GitHub;
a workflow definition alone does not prove a successful run.

## Limits

Restore depends on the saved per-face backup. Remeshing, joining different meshes,
or deleting backup attributes can remove provenance. New faces without a backup
are skipped; deleted original material data cannot be reconstructed. Assignments
made before version 1.3 contain no recoverable backup. Shared Mesh data retains
Blender's shared face-index behaviour; manual later material assignments are skipped.
Edit Mode actions finish in Object Mode for native Global Undo, and Tab resumes editing.
Global Undo must be enabled in Blender for normal Undo/Redo.

The former third-party room is excluded from the current tree and package after
the owner confirmed that its source was unknown. The owner explicitly approved replacing the initial publication history to remove
the old input from main. No deletion of detached Git objects or GitHub caches is claimed.
Texture ownership is described in ASSET_NOTICE.txt and docs/LICENSING.md.

Blender 5 test-harness differences were corrected: lazy UV pin attributes and
removed MeshUVLoop selection accessors. Runtime code never writes UV coordinates.
